# 跨品牌字幕直链分块续签

日期：2026-09-24  
状态：已按现有台账与用户授权自审通过，进入 implementation plan  
范围：assrt 字幕包在 115 / 光鸭 / 123 的落盘链路

## 背景

assrt 的 `detail()` 下载地址是短生命周期直链。真机证据显示，同一地址在生成后约 4 分钟仍可用，6 分钟返回 HTTP 402；官方接口也明确提醒下载地址具有有效期。

当前 sandbox 在一次 `transferSubtitle` 中先调用一次 `detail()`，再把整个文件列表交给网盘适配器。大包在适配器内部逐文件 resolve、提交或轮询时，尾部文件使用的 URL 已经老化：

- 123：每条 resolve 约 5–6 秒，75 文件包一次性处理时 0 落盘；逐文件 resolve → 立即 submit 的探针 23/24 成功。
- 115：168 文件包真盘落 120、48 超出窗口；整包批量预算修复已合并，但批量仍不能让一份旧直链永久有效。
- 光鸭：字幕走逐文件 `create_task`，视频成功后的字幕包曾连续 3 次失败；其中有配额错误，直链老化仍需通过分块续签隔离验证。

## 目标

1. 字幕包分块处理，每块开始前重新调用 `detail(candidateId)`，只把新生成的直链交给该块的网盘适配器。
2. 保留各品牌已有语义：
   - 115 继续优先使用 `transferSubtitleUrls` 整包批量接口和预算保留额。
   - 123 继续逐文件 resolve → 立即 submit，以目录为准认领。
   - 光鸭继续逐文件 `transferSubtitleUrl`，连续失败熔断与鉴权错误语义不变。
3. 字幕仍是软目标：部分成功返回真实落地名和失败原因，不阻塞视频交付。
4. 不凭猜测新增光鸭配额限制；配额错误继续原样作为 providerMessage 记录。

## 非目标

- 不改变 assrt 搜索、候选排序或 agent 的字幕语义判断。
- 不延长、缓存或持久化 assrt 直链；每块只在需要时重新获取。
- 不改变 115 的 300 次硬预算、40 次收尾保留额或 #261 的批量账目规则。
- 不为某个品牌加入硬编码的“每日字幕次数”配额。
- 不触碰用户明确自行清理的 123 历史 staging。

## 设计

### 分块边界

新增一个字幕续签块大小常量，默认 24 个文件。这个值是保守的初始参数：按 123 已测的约 5–6 秒单条 resolve，24 条约 2–2.5 分钟，给提交和抖动留下直链寿命余量；实际成本仍由品牌 executor 自己控制。

`TaskSandbox.transferSubtitle` 的流程改为：

1. 第一次 `detail(candidateId)` 得到完整文件列表，过滤非法扩展名和 `._` AppleDouble 文件。
2. 按稳定文件身份切成最多 24 个文件一块。稳定身份使用 `filename` 加同名文件出现序号，避免重复文件名互相覆盖。
3. 第一块直接使用第一次 `detail()` 的结果；从第二块开始，每块开始前重新 `detail(candidateId)`；每一块都只把当前新生成的直链交给适配器：
   - 按稳定身份从新列表中挑出本块对应文件；
   - 调用现有 `storage.transferSubtitleUrls`；
   - 立即记录本块真实 `landedFilename`、失败状态和最后 providerMessage。
4. 某个后续块无法重新 detail 时，停止后续块，保留之前成功落盘的结果，并返回软失败原因；不拿旧 URL 继续撞。
5. 块内提交失败由 executor 原有逻辑处理；sandbox 只汇总结果，不重复提交。

如果候选包文件总数不超过块大小且文件名唯一，仍只调用一次 `detail()` 和一次现有落盘入口。重复文件名必须分到不同的适配器调用中，仍按顺序处理，避免 assrt 突发限流和网盘任务竞态。

### 文件身份与落地汇总

新增纯函数负责：

- 过滤可落盘字幕文件；
- 为重复 `filename` 分配稳定 occurrence key；
- 从刷新后的 detail 结果中匹配当前块；
- 将各块 `SubtitleLandingResult` 合并为原有 `landedFilenames` 与软错误格式。

匹配不到某个旧文件时，该文件只记录为未尝试/刷新后不存在，不复用旧直链，也不误报已落盘。123 的 `name(1).ext` 真实落地名继续由 executor 返回并透传。

### 预算与失败

分块会增加每块固定的目录/快照开销，因此 115 的每块调用仍必须经过既有 `Pan115ApiGuard` 预检；任何预算不足由 115 executor 返回现有 `SUBTITLE_BUDGET_INSUFFICIENT`，不能通过 sandbox 绕过。

品牌鉴权错误继续抛出并冻结网盘；普通直链过期、配额、任务未落盘等继续软失败。分块层不把“配额已满”解释成“没有资源”。

### 可观测性

每个字幕块在 agent step 返回的 `chunkDiagnostics` 中保留：块序号、请求文件数、detail 刷新是否成功、成功落盘数、未落盘数和最后错误名。URL、token 和 provider 原始凭证不写日志。已有字幕工具返回结构保持兼容，新增字段只用于诊断和测试。

## 测试与验收

### 单元 / 集成

- 单块包只 detail 一次，落盘入口调用一次。
- 多块包在每块前重新 detail，第二块使用刷新后的 URL；旧 URL 不会传入第二块。
- 重复文件名按 occurrence 正确匹配，123 的 `(1)` 落地名透传。
- detail 刷新失败时保留已成功块，后续块不提交，返回软错误。
- 115 executor 的预算预检仍生效，分块不能让收尾保留额被吃掉。
- 123、光鸭的现有逐文件/连续失败/鉴权错误测试继续通过。
- 变异测试删除“块前重新 detail”时必须变红。

### 真盘

在隔离目录分别验证：

1. 123：至少 40 文件字幕包，确认每块使用新 detail，目录按原名和 `(1)` 双胞胎全部认领。
2. 115：大包验证尾部块的 URL 在窗口内提交；记录每块预算和最终收尾余量。
3. 光鸭：字幕包验证分块后不复用过期直链；配额错误单独记录，不把它与直链过期混为一谈。

所有真盘 smoke 完成后删除隔离目录和临时凭证副本，不部署生产；合并后按用户既定发行节奏统一发布。

## 自审结论

- 目标、非目标、三盘差异和失败语义一致。
- 没有把单用户网盘接入扩成新预算平台，也没有改变现有 executor 契约。
- “每日 1000 次”由用户提供的光鸭会员事实保留为运行环境信息，不写入代码规则。
- 块大小 24 是可测试的初始参数；若真盘数据证明不合适，只能在测试和 smoke 证据后调整。
